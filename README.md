# ピコぬ市公式ホームページ

架空自治体「ピコぬ市」の公式サイトです。GitHub Pagesでの公開を想定した静的サイトです。
「行政が本気で運営している架空自治体サイト」という空気感を大切にしています。

公開URL: `https://9f5v4mzdqd-dot.github.io/pikonu-city/`

## ディレクトリ構成

```
pikonu-city/
├── index.html                トップページ(お知らせ・サービス・施設・PR動画・キリ番など)
├── 404.html                  存在しないURLにアクセスした際のページ(GitHub Pagesが自動表示)
├── favicon.svg / favicon.ico / apple-touch-icon.png   ファビコン(市章)
├── robots.txt                 管理用ページ(*-admin.html)のクロール除外設定
├── css/style.css              共通スタイルシート
├── js/common.js                共通ヘッダー/フッター/アクセシビリティ/検索機能
├── data/
│   ├── piconu-diary.json      ピコぬくん業務日誌のデータ
│   ├── gendaibyo-db.json      現代病データベースのデータ
│   ├── gairai-archive.json    外来シリーズ書庫のデータ
│   └── search-index.json      サイト内検索用インデックス
├── news/                      お知らせ(18記事)
│   ├── index.html             お知らせ一覧
│   └── news-YYYYMMDD-NN.html  お知らせ詳細(日付+連番で命名)
├── services/                  くらしの情報(住民票・戸籍・ごみ収集・現代病相談 等、10ページ)
├── facilities/                施設案内(市役所・クリニック・博物館・図書館・商工会・交通局 等、45ページ)

├── images/                    画像(sections/ facilities/ museum/ kanko/ cable-tv/ jissen/ rekishi/ 等。運用ルールは下記参照)
```

`services/` `facilities/` `about/`の中の個別ページ一覧は、保守の都合上ここには
書き出していません。詳しくは `about/sitemap.html` を参照してください。

## 記録ファイルの役割分担

このリポジトリには、用途の異なる4つの記録ファイルがルート直下にあります。

| ファイル | 役割 | 更新頻度 |
| --- | --- | --- |
| `README.md`(このファイル) | サイトの技術仕様書。構成・運用ルール・仕組みの説明 | 仕組みが変わったとき |
| `CHANGELOG.md` | 変更履歴。「いつ・どのファイルに・何をしたか」を時系列で記録 | 変更のたびに |
| `IDEAS.md` | 未実装・検討中のアイデア帳。実装済みになったら削除する | アイデアが出た/実装されたとき |
| `pikonu-city-seisaku-rireki.md` | 制作者(三笠イマ)個人用の制作日記 | 制作者本人の任意 |

新しいページや機能を追加したときは、`README.md`(仕組み自体が変わった場合のみ)と
`CHANGELOG.md`(必ず)の両方を更新する。`IDEAS.md`に載っていたアイデアを実装した場合は、
該当項目を`IDEAS.md`から削除する。

## 画像・PDF・音声フォルダの運用ルール

### images/facilities/

既存の施設・課ページ用画像を保存するレガシーフォルダ。

現在使用されている既存ファイルは移動せず、そのまま維持する。
過去ページの画像パス変更による表示不具合を防ぐため、既存画像の移行作業は行わない。

### images/sections/

2026年8月1日以降に作成する施設・課ページ用の新規画像保存先。

対象：

* 市役所
* クリニック
* 各課ページ
* その他、行政組織・担当部署に関する画像

images/facilities/の増加による管理負担を防ぐため、今後の新規追加分はこちらへ保存する。

### その他の画像フォルダ

用途別フォルダは従来通り運用する。新規画像は内容に最も適したフォルダへ保存する。

例：

* images/kanko/ → 観光関連
* images/ikimono/ → 生き物・自然関連
* images/banners/ → バナー画像
* images/goods/ → グッズ・商品関連
* images/icons/ → アイコン関連
* images/jissen/ → 不要不急実践帳のカード画像
* images/rekishi/ → 市史・未整理資料関連の画像

用途に合うフォルダがなければ、新しいサブフォルダを作ってよい。

### pdfs/

2026年8月3日、ルート直下に散らばっていたPDFを整理するために新設。

* 複数号にわたるシリーズもの(広報誌・だより等)は `pdfs/シリーズ名/` のサブフォルダを作り、
  その中に `シリーズ名-YYYYMM.pdf` の形式で保存する(例: `pdfs/koho-nukapiko/koho-nukapiko-202608.pdf`)
* 単発のPDF(点数表、チラシ、カレンダー等)は `pdfs/` 直下にそのまま保存する

### audio/

FMピコぬの各番組音源、PR動画、ケーブルテレビ番組の音声・動画をまとめて保存する。

* 番組ものは `番組名-epNN.拡張子` の連番形式で保存する(例: `fukabori-radio-ep01.mp3`)
* 音声のみの番組は `.mp3`、映像ありの場合は `.mp4`(同じ回で両方存在する場合もある)
* テーマ曲など単発の音源はそのまま `曲名がわかるファイル名.mp3` で保存する

## 共通ヘッダー/フッターの仕組み

ヘッダー・フッター・グローバルナビ・パンくずリストは `js/common.js` が
JavaScriptで動的に生成します。各ページのHTMLには本文(`<main id="main">`)のみを
記述し、`</body>` の直前で以下のように呼び出します。

```html
<script>
  window.PAGE_META = {
    nav: "news",                              // グローバルナビの現在地(home/news/services/facilities/gaiyou/about/piconu-chat/radio)
                                               // 「市の概要」配下は "gaiyou"、「市政情報」配下は "about" (別キーなので混同注意)
    breadcrumb: [{ label: "お知らせ", href: "index.html" }, { label: "ページタイトル" }]
  };
</script>
<script src="../js/common.js"></script>
```

`js/common.js` は自身の `<script src>` からサイトルートまでの相対パスを自動計算するため、
ディレクトリの深さに関わらずページ側で相対パスを調整する必要はありません。

新規ページの `<head>` には、ファビコン3点(`favicon.svg` `favicon.ico` `apple-touch-icon.png`)
へのリンクも忘れずに含めます(既存ページの `<head>` をコピーするのが確実です)。

## 新しいページを追加する手順

1. **着手前に確認する**: `about/sitemap.html`で似たページが既にないか、
   `CHANGELOG.md`の直近の記録で関連する変更が進行中でないかを確認する。
2. **置き場所を決める**: 「施設・組織自身についての情報」なら `facilities/`、
   「市民が行う手続き・様式」なら `services/`、それ以外の市政記録・お楽しみ
   コンテンツは `about/` に置く。迷ったら「これは場所の説明か、手続きの説明か」
   で考える。`about/`内で「市の概要」か「市政情報」かで迷ったら、下記
   「『市の概要』と『市政情報』の区別」を参照する。
3. 該当ディレクトリにHTMLファイルを作成する。既存の近いページ(例: `services/juminhyo.html`)
   をコピーし、`<title>` `<meta description>` `<h1>` 本文、`window.PAGE_META` を書き換える。
   本文の`<p>`タグ内など、ブラウザ表示にそのまま反映される長文には、改行を入れず1行で
   記述する。`<ul>`の`<li>`や`<table>`の行など、改行が見た目に影響しない構造化された
   タグは、従来通り改行して読みやすく書いてよいですぬ。
4. **一覧ページに反映する**: 一覧ページ(`news/index.html`、`facilities/index.html`、
   トップページの該当セクション、`about/sitemap.html`)に必要に応じてリンクを追加する。
   お知らせ記事以外の新規ページは `data/search-index.json` にも追加する(お知らせ記事は
   自動反映されるため対象外)。関連する既存ページのサイドバー「関連情報」にも、
   相互リンクになるよう追加する。
5. `CHANGELOG.md`に追記する。`IDEAS.md`に該当項目があれば削除する。



## 「市の概要」と「市政情報」の区別

グローバルナビの「市の概要」と「市政情報」は、次の基準で分類する。新しいページを
`about/`に追加する際は、どちらに属するかをこの基準で判断すること。

### 🏙️ 市の概要

ピコぬ市そのものを知るための情報。市の基本情報・特色・歴史・文化・観光・市のシンボル・
市にまつわるコンテンツなどをまとめる。

→「ピコぬ市ってどんな市?」に答える場所。

入るものの例:

* 市の概要
* 市長のごあいさつ
* 市の歴史
* 市の花・市の鳥
* 生き物図鑑
* 観光案内
* 統計資料
* FMピコぬ
* ピコぬくん関連
* 各種ゲーム・コンテンツ
* 広報ぬかピコ デジタルアーカイブ

### 🏛️ 市政情報

ピコぬ市の行政運営に関する情報。条例・制度・行政組織・審議・会議・職員など、
自治体として市がどう運営されているかに関する情報をまとめる。

→「ピコぬ市は行政として何をしている?」に答える場所。

入るものの例:

* 条例集
* パブリックコメント
* 議事録・会議録
* 審議会・附属機関一覧
* 職員採用情報
* 行政構造図
* 部署別電話番号一覧
* その他、行政運営に直接関係する情報

**一言で線を引くなら**: 市の概要 = 「この市はどんなところ?」/ 市政情報 = 「この市はどう行政を運営している?」

## 簡易CMSパターン(GitHub API直接呼び出し方式)

サーバーを持たない静的サイトのため、GitHub REST API をブラウザから直接呼び出す方式で
簡易CMSを実現している。同じパターンが現在3つのデータに使われている。

| データ | 公開ページ(読み取り専用) | 管理フォーム(非リンク) |
| --- | --- | --- |
| ピコぬくん業務日誌 | `about/piconu-diary.html` | `about/piconu-diary-admin.html` |
| 現代病データベース | `facilities/gendaibyo-db.html` | `facilities/gendaibyo-db-admin.html` |
| 外来シリーズ書庫 | `facilities/kiroku-nuka-clinic-archive.html` | `facilities/kiroku-nuka-clinic-archive-admin.html` |

- **公開ページ**: 対応する`data/*.json`を`fetch`で読み込み、一覧表示・検索するだけの
  静的な読み取り専用ページ。
- **管理フォーム**: サイトのナビゲーションにはリンクしていない(直接URLを知っている人のみ
  アクセス可能。`robots.txt`でクロールも除外)。GitHubのPersonal Access Token
  (該当リポジトリの Contents: Read and write 権限のみを付与)を入力すると、ブラウザから
  直接対応する`data/*.json`を書き換えて投稿・編集・削除できる。各データの1件はUUIDの`id`
  を持たせて識別している。

新しく同種のCMSを増やす場合も、この3つのいずれかの管理フォームをコピーして
`FILE_PATH`を書き換えるのが確実。

## サイト内検索(`data/search-index.json`)

ヘッダーの検索ボックス(`js/common.js`)は、次の2つを組み合わせて検索結果を出す。

1. `data/search-index.json` — お知らせ記事を除く全ページを手動でリストアップしたファイル。
   1件は `{ "title": "...", "url": "services/juminhyo.html", "category": "くらしの情報" }` の形。
2. `news/index.html` — お知らせ記事は`.notice-list`をその場で解析して自動的に検索対象に含める
   (`href="#"`の未作成記事は自動的に除外される)ため、`search-index.json`への追加は不要。

**注意**: 新しくページを追加したとき、`search-index.json`への追加を忘れると、
そのページはサイト内検索でヒットしなくなる(お知らせ記事は自動反映されるため対象外)。

## GitHub上での編集ワークフロー(運用メモ)

このリポジトリは基本的に GitHub の Web UI(またはブラウザ内エディタ github.dev)から
直接編集して運用している。

- 既存ファイルの中身を書き換える: 対象ファイルを開いて鉛筆アイコン(Edit this file)
- 新規ファイルを追加する: 対象フォルダを開いた状態で「Add file」→「Create new file」
  (テキストファイル)または「Upload files」(画像・PDF・動画などのバイナリ)
- 新しいフォルダごと追加したい場合は、`Create new file` でファイル名に
  `フォルダ名/ファイル名` の形でパスを含めて入力すると、フォルダが自動生成される
- 複数ファイルをまたぐ変更は github.dev(リポジトリ画面で `.` キー)を使うと、
  検索・一括置換やSource Controlでのまとめてコミットがしやすい
